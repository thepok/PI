# GPT Pro operating guide

Pro is for hard creative mathematics at the actual-π signed boundary. It does
not do Lean, repository editing, workflow work, navigation, or knowledge
integration.

## Lifecycle

- Keep up to three useful conversations active.
- Never cancel an active run; slow Pro turns receive time.
- Resume an interrupted saved command with the identical prompt. Do not submit
  a duplicate unless the original was proved never submitted.
- Use at most five follow-ups per conversation, only when independent audit
  finds a genuinely new surviving lemma with a sharply isolated next step.
- Notify Marcel immediately for login, account, browser, or capacity action.
  Otherwise report only substantial independently confirmed mathematics.
- Work from GitHub/local `main`; Pro returns a memo and never edits the repo.

## Small prompt packet

Give every run only:

1. [`FRONTIER.md`](FRONTIER.md);
2. the relevant file among
   [`T189_FMR_R1_R2.md`](knowledge/pi/active/T189_FMR_R1_R2.md) and
   [`FIRST_OPEN_PI_LEMMA.md`](knowledge/pi/active/FIRST_OPEN_PI_LEMMA.md);
3. at most three nearby warnings from
   [`ATTEMPT_LEDGER.md`](knowledge/pi/active/ATTEMPT_LEDGER.md);
4. direct Lean links only when theorem semantics matter.

Do not ask Pro to map the repository and do not load
`knowledge/pi/archive/`. The archive is for a specific novelty/provenance
check after an idea exists, never default context.

## Shared mathematical target

T189 is fixed. At a positive natural-diagonal node,

```text
G_d = old child gain,
D_d = fresh child gain = q(Delta_0+Xi_d)-21/10.
```

Fresh-monotone regeneration asks for one shared digit with

```text
D_d>0 and G_d+D_d>0.
```

The honest split is R1 (`some D_d>0`) and R2 (the same digit covers its old
deficit). Separate witnesses are invalid. The first open arithmetic rung is a
quantitative actual-π lower bound for a literal paired predecessor sector that
implies R1, or a strictly shorter aligned theorem implying FMR. It must not
assume the unbounded reached path it is meant to construct.

Every proposed component must answer:

> Where does target-signed Archimedean information for the actual π enter?

Symmetry, mean zero, almost-everywhere behavior, denominators, periodicity,
congruences, unsigned energy, rational shadows, and finite replay are not that
source by themselves.

## Three differentiated slots

1. **Ladder designer:** seek the shortest non-tautological ladder from the
   first actual-π input through R1/R2 to the existing consumer.
2. **Rung prover:** genuinely try to prove the shared first open π-specific
   rung, reducing it only when a precise fatal step is found.
3. **Adversary:** attack that same rung; repair its critical step or close it
   with the narrowest exact separator.

Prompts stay open to new arithmetic, special-function, modular, Padé,
hypergeometric, BBP, Machin, or other mechanisms, but a representation counts
only when it feeds the named signed rung. Use PaperSearch early as building
material and distinguish almost-everywhere results from pointwise π theorems.

## Required memo

Return exact statements, quantifiers, constants, derivations, stress tests,
claim boundary, and shortest verified consumer path. End with a compact list
of every serious attempt: proposed lemma, first fatal line or surviving step,
and genuinely new input required.

Pro output is untrusted. The operator independently audits mathematics and
novelty, integrates one concise canonical result, and performs any Lean work.
Equivalent criteria, duplicate no-gos, and workflow changes are not π progress.

## Cleanliness

The active knowledge core stays between 20 and 40 files, with at most ten live
separators and one compressed ledger. New results replace or update canonical
active files; superseded notes move to the archive immediately. Never let the
attempt ledger regrow into transcripts or make historical material routine
prompt context.
